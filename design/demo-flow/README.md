## 共同布局

- 桌面网页，目标设计视口 1440 × 1024；生成图作为视觉参考，实际布局使用响应式约束。
- 顶栏：游戏名称、版本、模型连接状态、设置、导出。
- 左侧约 35%：对话、操作记录、固定输入框。
- 右侧约 65%：固定位置的正方形游戏舞台、运行状态、控制和结果。
- 白色工具界面，深靛色游戏舞台，青绿色主要操作，琥珀色进行中状态。
- 用户消息右对齐并与 AI 消息明确区分。
- 代码差异按需展开；完整编辑器不占用默认工作区。

## 实现时的交互约束

1. 点击游戏获得输入焦点；点击输入框后，游戏不消费打字按键。
2. 测试期间只有 AI 控制测试会话；停止时取消后续任务，释放按键，在可安全中断的位置结束当前操作，然后交回控制权。
3. 操作状态来自真实工具事件，截图来自实际运行，不用预设计时器模拟完成。
4. 图片中跳跃轨迹仅表示测试可视化方向，若实现，必须由实际采样数据生成。
5. 成功判断需要实际越墙并落地；主按钮“亲自试玩”加载通过验证的对应版本。
6. 失败时保留上一可玩版本，并展示本次实际错误或未通过原因。
7. “回放本次测试”使用真实测试记录，明确区别于当前实时试玩。
8. 撤销恢复源码与资源版本并重启游戏，同时同步展示版本与验证状态。
9. API Key 从设置弹窗由用户输入，默认仅在当前会话保留；主界面和演示画面不显示密钥。
10. 原型阶段如使用模拟数据，必须明确标识；设计稿中的文案不构成测试证据。
