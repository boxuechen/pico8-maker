# Prototype Instructions

Keep the demo minimal: dark assistant-ui chat and pico8-web-player inside the pixel console shell. Keep PNG as the default observation. Support optional cropped ASCII pixel inspection with the actual frame palette; do not infer object labels from colors.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Cart shelf and storage (2026-11-12)

Static site only, never a server: carts live in the browser. `src/cart-store.js` stores every cart in IndexedDB (`pico8-maker`: `carts` keyed by id, `meta.session` with currentId/active), and falls back to memory (with a visible warning) when IndexedDB is unavailable. There is no migration from the old single-project localStorage snapshot. Home shows a "My carts" shelf (continue, save .p8, duplicate, delete with confirmation, SAVED / NOT SAVED YET status, persistent browser-only notice) and LAST CART top right. A home prompt always starts a new cart; workbench prompts continue the current one. Switching carts reuses the player and recreates the agent per cart; stale agent updates are ignored. Only content changes (transcript, versions, revision, label, title) bump `updatedAt`.

## Cart workspace (2026-11-12)

The agent has one writable game file, `/cart/main.lua`, and a shared read-only document mount, `/extensions/pico8/`. `CartWorkspace` owns game file mutations; `knowledge-files.js` loads manifest-listed static documents by version with hash validation and caching; `knowledge-env.js` composes the two for Pi Durable's built-in `read`. Built-in `edit` stays bound to the cart only. There is no shell. `Game.draft` is the working source/resource snapshot; `load_game` compiles and commits it. Failed compilation retains the draft and the last committed playable version. Undo resets the draft; export uses committed source.

Publish original Markdown/Lua files, not a JS object containing their bodies. Automatically read AGENT.md, MACHINE.md, the generated default palette, REFERENCE_INDEX.md and the generated skills catalog before opening a session; other files are read on demand with offset/limit support. Remove obsolete loading paths rather than adding compatibility: there is no read_reference tool or pico8-knowledge.js bundle. Keep Markdown links as virtual file paths, validate recipes, and never mount maintainer/research documents by directory-wide copying.

## Workspace and session product direction (2026-11-12)

One home-screen cart corresponds to exactly one project workspace. Use "cart" / "My carts" in the user-facing project UI; workspace is the internal boundary for that cart's files, versions and conversation sessions, not an additional user-facing container. Creating a cart creates its workspace; continuing a cart opens that workspace in the workbench. A downloaded `.p8` is an export of the game's committed content, not a backup of its conversation sessions or full workspace.

The workbench activates only one cart workspace at a time. Select carts on the home shelf; do not add an in-workbench workspace switcher. A collapsible left sidebar uses assistant-ui ThreadList primitives and the external-store thread-list adapter: one domain session equals one UI thread. Desktop has conversation list, chat and shared preview columns; the chat/preview divider excludes the sidebar width. Narrow desktops default to a collapsed icon rail; mobile uses a modal conversation drawer. Persist collapse preference; disable conversation creation/switching/rename during runs and transitions, while collapse remains available. The header keeps the cart title; sessions get their own title from the first request.

A cart record owns shared `versions`, `revision`, `workingDraft`, `contentVersion`, and `label`, plus `sessions` and `activeSessionId`. Each session owns its ID, title, transcript, composer draft, interrupted flag, timestamps and last observed source version. The browser navigation record stores home draft and current cart/page separately. Storage accepts schema version 3 only; there is no old cart migration or string-version compatibility.

Only the active session has a live Pi Agent/Harness; replacing it closes its watch/harness before opening the next session. Persist each transcript to IndexedDB, restore model context without replay, and reject callbacks with stale generation/cart/session identities. Switching sessions never calls switchProject or resets game versions. New and resumed sessions receive default PICO-8 documentation and a project section instructing them to read the current shared file; contentVersion detects changes from other conversations, including uncommitted source and resource edits. This retains application-owned persistence, not automatic resumption of Pi tasks after a reload. Duplicating a cart copies its sessions with fresh IDs; deleting a cart removes its embedded sessions. Session switching, draft edits and restored snapshots should not reorder the shelf unless content changes.

Cart creation asks for a name before entering the workbench; blank names receive monotonically numbered `New Cart1`, `New Cart2`, etc. Keep explicitly created empty carts on the shelf. Cart names are independent of first-message conversation titles. Conversation titles can be renamed without changing the cart name; manually renamed empty conversations retain their name on first send.

Agent completion: leave Pi Durable's `maxTurns` unset in the interactive app. Let the model decide when to finish; do not impose an application-level tool-round cap or require users to send “继续测试” to bypass one. Preserve manual STOP/cancellation.

Completion workflow (2026-11-12): scope new games and focused edits to the request, verify the main action and representative outcome/retry, then deliver a final reply. Prevent open-ended polish and repeated input/screenshot loops through the model-facing AGENT/playtest instructions and precise tool descriptions. Repeated observations of the same frame add no gameplay evidence. If tests stop producing useful evidence, inspect the relevant source or change the test setup; report an unresolved blocker honestly. Do not require unavailable audio/live-variable evidence. A final reply ends the run without a separate finish tool; preserve natural completion, uncapped tool rounds and manual STOP.

Agent defaults: use Pi Durable's retry and automatic compaction policies and Pi AI's model output/timeout defaults; disable only nested transport retries so Durable owns retry/backoff. Default thinking to high, expose supported levels in model settings via Pi's capability catalog, persist the user's choice, and resolve unsupported levels with Pi's clamp. Custom endpoints expose their context/output capacities explicitly. Persist transcript entry identities, context heads and edits (remapped on restore), plus thinking signatures; keep old chat visible and hide internal compaction summaries from the chat UI. Legacy flat transcripts remain readable. Restore never replays tools. Align test input with the player's 600-frame maximum and use its default VM instruction safety budget. Do not impose an additional source-character limit in tools or cart storage. Preserve sequential game operations, cancellation, Worker timeouts and existing history retention.

Empty preview: keep Preview selected by default, but new carts start with an empty working file, no committed versions and revision 0. Show an empty screen until a game is successfully loaded; do not seed the project with the little-wall demo or select a community game implicitly on Play. Disable play/restart/export for empty carts. Community games still play when explicitly selected. The first generated game is v1; existing authored carts retain their content.

Source organization decision (2026-11-12): retain one writable Lua source file, `/cart/main.lua`. Do not add multi-file Lua authoring for now. Phase-one native cartridge resource separation is authorized. Keep one Lua file and use structured read_assets/edit_assets tools for static resources. Store complete {source, assets} snapshots (assets is canonical hex of 0x0000–0x42ff) for drafts and versions. Runtime, undo, recovery, gallery return and export load complete .p8 carts. Resource-only edits create versions; failures retain both drafts and the previous complete cart. The Resources tab is read-only, with working/committed versions, sprite/map previews and SFX/music data. Author 256 sprites and only 128×32 map cells to avoid shared-memory writes through resource tools; runtime Lua retains normal memory behavior. Do not add paint tools, a map editor, an audio sequencer, imports or legacy migration in this phase.

## Extension and skills (2026-11-13)

Use a thin Pi Durable extension for executable tools and host capabilities, and separate Agent Skills-style SKILL.md files for create/edit/assets/playtest workflows, following Game Studio's entry/specialist design. Publish only skill name/description/path in a generated startup catalog; full bodies are read on demand with the existing versioned read-only document mount. Reuse skills already in context. Keep completion/evidence essentials in the compact AGENT router. Do not move workflows into tool descriptions or add automatic onYield/after-run continuation loops. Pi Durable 1.5.2 has no native coding-agent skill/package loader; this fixed static catalog is app-owned, not a replacement plugin runtime. Preserve the existing tools, schemas, sequential execution, manual STOP and model-led completion.

Durable contract fixes (2026-11-13): read_game is a bounded first-page read; follow read line continuations, or source-only UTF-8 byte ranges for oversized lines. Keep the output bounds without imposing a source cap. Freeze project context at request entry so the Agent's own edits cannot invalidate new evidence; detect external changes again at the next request. Report advisory draft budgets and explicit committed/failed-draft observation attribution. Read the matching skill for an action even when the change seems trivial; a compacted mention is not a retained full skill body.

Real-model skills evaluation lives at the dev-only evaluation.html and scripts/evaluation/skills-*. It reuses this browser origin's saved configuration, creates disposable carts, archives redacted transcripts and execution snapshots under .cache/evaluations, and does not persist test carts into the user's shelf. Its time/tool budgets apply only to evaluation. Preserve failed attempts and distinguish automatic scope checks from independently reviewed gameplay; do not turn a passing small sample into a quality guarantee.
