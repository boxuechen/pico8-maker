- Each cart owns shared source, resources, versions and the change counter. Sessions own history, composer drafts and titles. Keep schema version 3 and readable flat transcript recovery. IndexedDB stores carts, with a visible memory fallback. Preserve transcript heads and thinking signatures on restore, with interrupted tool results represented explicitly.
- Keep only one live Agent for the active session. Block cart and session switches during runs, reject stale callbacks and keep the cart runtime across conversation switches. Restore context without replaying tools. Freeze the shared project baseline per user request and detect intervening changes on the next request.
- Keep model settings at the composer. Save them in the browser by default with opt-out and clear controls. Send requests directly to the selected provider, keep keys out of transcripts and exports, and preserve Pi native protocol and model capability checks.
- Preserve one comparison snapshot from before the user's latest modifying request, not an intermediate tool commit. Preview can switch between that snapshot and the current cart without changing source, export or test state. Restore current preview before the next Agent request; retain the comparison across read-only requests.
- Pi Durable owns retry and compaction. Use provider output/timeout defaults and medium thinking clamped to model support. Preserve sequential tools, STOP, bounded WASM execution and model-led completion without a tool-round cap or automatic continuation.

## Agent flows

- New conversations use the **shell flow** (decided 2026-11-14 after the evaluations in docs/shell-flow-migration.md): pi-durable's read/write/edit/bash over a just-bash shell with `/cart/main.lua` mapped to the cart draft, the read-only pico8 skill at `/skill/pico8`, `p8 check/run/look/new/export` running the player runtime in its own Worker, and the `read_assets`/`edit_assets` resource tools. Code lives in `src/pico8/shell/`; the skill source is `src/pico8/shell/skill/` (bundled by `scripts/prepare-shell-skill.mjs`), shared with `lab/local-agent`. A p8 command that runs main.lua commits a changed draft through `load_game` and reports it on a `Maker:` line; tested routes replay through `reset_game`/`press_buttons` (first per revision, then only g.mode changes). The sound bank goes only into a new cart's first version.
- Each conversation stores its flow. Conversations with history and no stored flow are frozen-flow conversations and stay so; `?flow=frozen` starts a new conversation on the frozen flow. Evaluations default to the shell flow (`S4_FLOW=frozen`, `SMOKE_FLOW=frozen`, `run-case.mjs --flow frozen` for the other).
- The **frozen flow** (tools and schemas, result DTOs, startup sections AGENT/MACHINE/WORKFLOW/host, reset skeleton, image retention, audio events and coverage facts) stays frozen at tag `agent-flow-freeze-2026-11-13` with player `69521e7` as the fallback; the shell flow reuses its `load_game`, `reset_game`, `press_buttons` and resource tools unchanged. Change either flow's agent-facing behaviour only with evaluation evidence and a before/after rerun recorded in docs/development-status.md. Do not remove the frozen flow before a separate decision.
- The "Knowledge and tools" rules below describe the frozen flow's contract; the shell flow follows them where it reuses that code (commits, versions, playtest records, resources, image retention).

## Knowledge and tools

- Keep one writable source file, `/cart/main.lua`, read through `read` with draft status and budget, and native draft resources edited through structured tools. The source and resources commit together after a successful load. Failed loads retain the draft and last playable version. Undo and export operate on complete cart snapshots.
- Publish English AGENT/MACHINE/WORKFLOW/base palette/host rules in a stable startup order, with dynamic project state last. Keep references versioned and read-only under `/extensions/pico8/`, loaded on demand. Do not restore skill routes or reading prerequisites. Preserve language/link/hash/receipt validation and keep the extension focused on capabilities. Reply in the user's language.
- For new games, establish and play a small complete action/feedback loop before expanding content, then finish the requested scope. Keep design patterns optional and preserve relaxed or expressive games. Verify short finite games from normal start through completion and retry on the final version; label seeded-progress checks separately. Keep numeric source advice nonblocking and bounded, and preserve native atomic editing and input validation before execution.
- Keep PNG as the default and preserve exact cropped ASCII pixels with the actual frame palette. Model PNGs are nearest-neighbor ×4 and report imageScale; crops stay native. Outgoing requests omit tool images from earlier user requests and keep the newest 16–31 in the current one; never alter stored transcripts. Observations do not advance time. Keep bounded source pagination, advisory budgets and evidence tied to its frame and cart revision. Validate input sequences before execution and report actual progress. Return only the final input frame by default; intermediate checkpoints are explicit. Resource previews read authored data without running the game.
- Record bounded playtest routes per cart, exposed through read-only `/cart/playtests.json` and run files. Keep frame images in the existing transcript. Debug execution marks the entire route debug before dispatch and keeps it through runtime errors and cancellation; only a compile-rejected chunk, which never ran, is dropped. After an executed error, allow state reads but require reset before input or more debug. Neither label is a pass verdict. Accept only steps for input; records use format version 3 with no legacy adapters or replay tool route. Load/reset creates a new test session with fresh memory saves. Keep recording updates outside contentVersion. Tap releases count toward the existing frame limit. Use the shared runtime inspection validator before dispatch; do not expose debug in live playback. State writes never alter authored source/resources or export.
- Report guest audio starts (sfx/music, voice, overMusic) from the test runtime as trigger evidence only. Report normal-input route coverage for the current revision when committing and in project context; never turn it into an automatic continuation or pass verdict.
- Run real-model checks through the local evaluator with disposable carts. Keep detailed runs in the ignored evaluation cache. Preserve failures when reporting results and distinguish scoped checks from gameplay quality. Evaluation tools and notes belong outside the model's published knowledge.

- For S4 result checks, use `npm run test:s4` and the explicit `eval:s4 -- --run --matrix <file>` CLI. Keep model credentials in per-endpoint environment variables; archive unavailable configurations as not_run and failed generations as errors. Freeze inputs and retain Agent normal-route coverage separately from the fresh-session state/pixel oracle. Scripted providers do not establish real-model quality.
