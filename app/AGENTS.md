# Prototype Instructions

Keep the demo minimal: dark assistant-ui chat and pico8-web-player inside the pixel console shell. Keep PNG as the default observation. Support optional cropped ASCII pixel inspection with the actual frame palette; do not infer object labels from colors.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Accepted UI direction (2026-11-12)

The user approved a PICO-8 official-site-inspired home screen: navy-black background, original community cartridge images with source/author links, pixel console, Proggy-style English labels, pink MAKE action, and readable Chinese body text. The large chat input stays visible in the first desktop viewport. First submission prompts for model credentials only when needed, preserves the draft on cancel, and automatically submits after “Save & start making”. The hero disappears on submission, revealing a resizable left-chat/right-live-preview workspace with the same theme. Preserve the real Agent/Pi/WASM chain, screenshot observation, cancellation, undo and export. Persist the current project's transcript, draft and game versions locally; restore model context without replaying interrupted tools. API keys and model settings are saved in this browser by default, as explicitly requested for static deployment; an opt-out and Clear saved settings action remain available. Requests go directly to the selected provider, never through a PICO Maker backend. Community cartridges play in the local player from embedded HTML data; author attribution links open official pages. They are not AI remix templates.

Homepage refinement: use the exact official p8tv_header background and pixel play button, reproduce the observed power-on coloured vertical/horizontal scan sequence, and keep a dense 6-left / 8-right cartridge layout plus More Carts. Prefer English homepage copy and Proggy typography. Embed original cartridge bytes in HTML at build/dev time, load them in the real local WASM runtime, and restore the user project before entering the workspace or sending to the agent. Never save gallery cartridges over the user's source/version history.

Workbench refinement (supersedes the earlier BBS post treatment): use Proggy for English body/input text (16px, 1.5 line height), readable Chinese fallbacks, and a separate monospace code font. Use assistant-ui-style left assistant / right user messages without visible role labels, avatars or post dividers. All large workspace surfaces, including topbar, chat, preview and composer surround, share #11141D. User bubbles and composer share #1E222D; use #303542 edges, #DADCE3 text and #9298A8 secondary text. Pink is reserved for primary actions, links and focus/selection. Assistant replies and collapsed tool records have no separate background. Use a two-line dark composer, retaining IME-safe Enter and SEND / STOP behavior. Group tools per assistant turn, expanded while running and collapsed when done, with distinct completed / failed / interrupted states; preserve raw Pi history and screenshot observation. Default desktop split is 58% chat / 42% preview, adjustable from 35% to 72%. Cap the shell at 540px (384px playfield); fullscreen can enlarge it. Clip the original banner to its existing shell silhouette in the workspace, keeping homepage imagery unchanged. Preview/code tabs and richer version controls remain a later iteration.

Compact player refinement: homepage and workbench share player-shell.css for the same vertical control strip on the right of the TV and small Proggy control hint at its foot. Anchor these elements inside the console so their position remains correct in fullscreen. Use a 540px desktop shell / 384px playfield for crisp 3x scaling when space permits, and align the player toward the top below the Preview heading. Scale down to fit narrower or shorter windows. Narrow layouts use 34% preview / 66% chat and a 180px shell cap.

Workspace navigation: show only the existing pixel spark as the accessible Back to home button in the top-left; keep full branding on the homepage. Use independent HomeHeader and WorkbenchHeader layouts. In the workbench, place the conversation title beside the spark in a single compact top row; remove the redundant chat heading row. Keep runtime, conversation and player state shared across page modes. Use the first user request for the display title so existing sessions are not stuck with the legacy 24-character truncation; truncate only visually with an ellipsis and retain the full title in the tooltip.

Model settings: the entry lives in the composer footer next to SEND / MAKE, showing the configured model; remove the global toolbar connection button. Reuse installed Pi catalogs and each model's native protocol for mainstream API-key providers, keeping image observation and tool calls. Distinguish regional/Token Plan credentials, clear key fields on provider or endpoint changes, and never persist keys in project exports or source control. Exclude OAuth-only/server-credential integrations from the plain API-key picker.

Homepage MAKE A GAME button: use explicit line height and comfortable horizontal padding, keep the button from flex-shrinking, and center it against the PICO-8 logo. Let the logo scale to available space so the CTA never looks clipped on narrower layouts.

Unified workbench header: chat title and Preview/status share the same 52px top row, aligned to the draggable content split. Extend the divider through the header, keep project actions at the far right, and remove any separate player heading. The player starts directly below with the same 20px top inset as chat. On narrow stacked layouts keep Preview in the compact top row and hide only the secondary status text.


PICO-8 knowledge: model-facing rules and references are English, compiled from docs/pico8-agent via prepare:knowledge. Keep replies in the user’s language. Preserve the pico8 extension sections, six tools, versioned reference output and legacy-history migration. observe_game supports png/ascii/both and validated screen-region crops. Other game tools keep PNG. Preserve full pixel grids and frame identity across tool output and history; observation must not advance time.
