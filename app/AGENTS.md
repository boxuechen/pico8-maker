# Prototype Instructions

Keep the demo minimal: dark assistant-ui chat and pico8-web-player inside the pixel console shell. Keep PNG as the default observation. Support optional cropped ASCII pixel inspection with the actual frame palette; do not infer object labels from colors.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Cart shelf and storage (2026-11-12)

Static site only, never a server: carts live in the browser. `src/cart-store.js` stores every cart in IndexedDB (`pico8-maker`: `carts` keyed by id, `meta.session` with currentId/active), and falls back to memory (with a visible warning) when IndexedDB is unavailable. There is no migration from the old single-project localStorage snapshot. Home shows a "My carts" shelf (continue, save .p8, duplicate, delete with confirmation, SAVED / NOT SAVED YET status, persistent browser-only notice) and LAST CART top right. A home prompt always starts a new cart; workbench prompts continue the current one. Switching carts reuses the player and recreates the agent per cart; stale agent updates are ignored. Only content changes (transcript, versions, revision, label, title) bump `updatedAt`.

## Cart workspace (2026-11-12)

The agent has one writable game file, `/cart/main.lua`, and a shared read-only document mount, `/extensions/pico8/`. `CartWorkspace` owns game file mutations; `knowledge-files.js` loads manifest-listed static documents by version with hash validation and caching; `knowledge-env.js` composes the two for Pi Durable's built-in `read`. Built-in `edit` stays bound to the cart only. There is no shell. `Game.draft` is the working source; `load_game` compiles and commits it. Failed compilation retains the draft and the last committed playable version. Undo resets the draft; export uses committed source.

Publish original Markdown/Lua files, not a JS object containing their bodies. Automatically read AGENT.md, MACHINE.md, the generated default palette and REFERENCE_INDEX.md before opening a session; other files are read on demand with offset/limit support. Remove obsolete loading paths rather than adding compatibility: there is no read_reference tool or pico8-knowledge.js bundle. Keep Markdown links as virtual file paths, validate recipes, and never mount maintainer/research documents by directory-wide copying.

## Workspace and session product direction (2026-11-12)

One home-screen cart corresponds to exactly one project workspace. Use "cart" / "My carts" in the user-facing project UI; workspace is the internal boundary for that cart's files, versions and conversation sessions, not an additional user-facing container. Creating a cart creates its workspace; continuing a cart opens that workspace in the workbench. A downloaded `.p8` is an export of the game's committed content, not a backup of its conversation sessions or full workspace.

The workbench activates only one cart workspace at a time. Select carts on the home shelf; do not add an in-workbench workspace switcher. A collapsible left sidebar uses assistant-ui ThreadList primitives and the external-store thread-list adapter: one domain session equals one UI thread. Desktop has conversation list, chat and shared preview columns; the chat/preview divider excludes the sidebar width. Narrow desktops default to a collapsed icon rail; mobile uses a modal conversation drawer. Persist collapse preference; disable conversation creation/switching/rename during runs and transitions, while collapse remains available. The header keeps the cart title; sessions get their own title from the first request.

A cart record owns shared `versions`, `revision`, `sourceDraft`, `sourceVersion`, and `label`, plus `sessions` and `activeSessionId`. Each session owns its ID, title, transcript, composer draft, interrupted flag, timestamps and last observed source version. The browser navigation record stores home draft and current cart/page separately. Storage upgrades an old single-transcript cart once into its first session, preserving source and drafts; all runtime code uses the new shape.

Only the active session has a live Pi Agent/Harness; replacing it closes its watch/harness before opening the next session. Persist each transcript to IndexedDB, restore model context without replay, and reject callbacks with stale generation/cart/session identities. Switching sessions never calls switchProject or resets game versions. New and resumed sessions receive default PICO-8 documentation and a project section instructing them to read the current shared file; sourceVersion detects changes from other conversations, including uncommitted edits. This retains application-owned persistence, not automatic resumption of Pi tasks after a reload. Duplicating a cart copies its sessions with fresh IDs; deleting a cart removes its embedded sessions. Session switching, draft edits and restored snapshots should not reorder the shelf unless content changes.

Cart creation asks for a name before entering the workbench; blank names receive monotonically numbered `New Cart1`, `New Cart2`, etc. Keep explicitly created empty carts on the shelf. Cart names are independent of first-message conversation titles. Conversation titles can be renamed without changing the cart name; manually renamed empty conversations retain their name on first send.
