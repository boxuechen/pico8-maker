# Current host

The application now installs the pico8 extension with file-backed English knowledge sections and the built-in read tool. Host capability text is generated from app/src/pico8/capabilities.js. This document is a maintainer description, not a registered reference or an additional persistent model section. Workspace operations, tool schemas and session limits belong in the host section and tool descriptions, rather than being repeated in AGENT.md.

- The cart has Lua source plus native sprite/map/audio resources. read_assets/edit_assets expose resource drafts, not live RAM; source and resources commit and export together. Procedural initialization remains supported.
- The source is one workspace file, /cart/main.lua. Game tools: read_game, load_game, reset_game, press_buttons and observe_game, plus built-in edit limited to main.lua and read for source and /extensions/pico8/ documentation. load_game takes optional complete source; without it, it commits the edited file and current resources. A failed load retains both drafts for fixing. There is no shell.
- Test input is player 0, up to 600 logical frames. Other game tools return PNG. observe_game defaults to PNG and supports ascii/both with optional {x,y,width,height} cropping at original resolution. ASCII includes all 16 actual display-slot color names, RGB values and display codes. Invalid regions fail; no completed frame is reported without stepping.
- Test and live player sessions are independent. Test persistence is memory; destroying its Worker loses that instance.
- No live-variable query or model audio return is available.
- Document reads use versioned static files, fetched on demand and cached across carts. They do not operate the game. /extensions/pico8/ is read-only; required entry documents load before a session opens.
- The generated skills catalog is a required entry document; full SKILL.md bodies load on demand. This fixed manifest-based integration belongs to the app, not Pi Durable's native API. Task workflows live in skills; the extension registers capabilities and minimal context.
- read_game returns the first source page within 2,000 lines / 50 KiB, with concrete read continuations. Normal source reads use Pi's line offsets; an oversized line uses source-only UTF-8 byteOffset/byteLimit ranges. Document reads retain the built-in line interface. These are output bounds, not source authoring limits.
- read_game diagnostics and runtime observations expose committedRevision, draftDirty and draftSourceBudget. Budget estimates are advisory; compressed size and official PICO-8 compatibility remain unverified. Observation cart.observed distinguishes committed frames from a failed draft and keeps cart revisions separate from runtime frame identities.
- The project section describes the baseline at the start of each user request. Own tool edits cannot trigger an external-change warning during that request; subsequent tool results provide current draft/commit state. A later request still detects changes made by other conversations.
