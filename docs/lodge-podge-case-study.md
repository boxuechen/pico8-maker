# Lodge Podge：从 ModRetro 案例到 PICO-8

## 参考与实验边界

参考 OpenAI 在 2026-11-09 发布的 [Build a game with ModRetro Chromatic](https://developers.openai.com/blog/build-a-game-with-modretro-chromatic)，作者 Kevin Whinnery。文章中的 Lodge Podge 是海狸采集材料、建造小窝的俯视角游戏；后续反馈包含让海狸更圆胖，以及加入泥和树叶。文章展示了生成、预览、反馈和修改的流程，不能据此判断一次生成成功率。

本实验沿用玩法主题和两轮反馈结构，代码、像素和音频由本地 PICO-8 Maker 的实际 Agent 生成。没有导入官方游戏代码、ROM 或美术资源，也不是逐像素复刻。使用浏览器已经保存的 DeepSeek Flash / high 配置，沿用现有知识和工具。外层 Codex 负责案例研究、提出反馈、搭建记录与试玩页面、独立复查；没有代写生成卡带中的游戏逻辑或资源。

这是一个案例、一个模型配置、一次连续两轮创作。没有对照组，不能证明知识蒸馏提高了质量，也不能用于比较 Codex 与 DeepSeek。

## 用户输入

第一轮：

> 做一个叫 Lodge Podge 的 PICO-8 俯视角小游戏：玩家控制一只可爱的像素海狸，啃倒小树收集木棍，在地图中央建成自己的窝。画面温暖可爱，有动作动画、音效和轻松的背景音乐，完成后能重新开始。

第二轮：

> 海狸再圆胖可爱一点，扁尾巴和门牙要容易认出来。现在草地太亮、细碎花纹太密，请让背景安静一点，角色、材料和窝更突出。参照官方案例，把建窝材料扩展成木棍、泥和树叶，让采集与建造有一点变化；各材料的来源和剩余需求要看得懂，开场就告诉玩家移动和采集的按键。保留轻松氛围、动画、音效和背景音乐。请用最终正常的初始状态实际玩通并检查重开，不要把预置资源或进度的调试结果当作完整通关。

每轮上限 15 分钟，没有工具次数上限。第二轮反馈来自外层观察，不是产品自动发现的问题。原始记录包含失败工具调用、临时调试版本和最终版本。

## 首版结果

首个可运行版本约 4 分 27 秒；整轮 9 分 9 秒，70 次工具调用、4 次工具错误、11 次成功提交。四次错误是观察区域和输入参数错误，后续恢复。

玩法有完整的采集、携带、自动交付、建窝和重开。画面有角色动画、树木和建造反馈；草地过亮、纹理密集，小尺寸材料不容易辨认。模型没有给首次操作留下充分的提示。

模型自己实际玩到 11/12，之后临时预置进度验证成功与重开，再恢复初值。因此模型的记录不足以证明最终版本正常起点可通关。外层随后使用最终未修改的 `.p8`，通过真正的 WASM 输入执行独立路线，观察到 12/12、完成面板，以及按 X 后的 0/12。共 52 个输入段、1351 帧，无运行诊断。独立路线不计入模型工具次数。

## 第二版结果

第二轮用时 10 分 19 秒，87 次工具调用、6 次工具错误；最后提交为 revision 24，草稿与提交一致。两轮总计约 19 分 28 秒、157 次工具调用。这是生成与修复时间，不包含外层研究、独立复查与页面制作。

背景从高亮草地改为较安静的绿色，角色重画为更圆胖的海狸，木棍、泥和树叶分别计数。开场加入操作提示，顶部显示交付进度，底部显示携带量。建造随着材料变化。实际试玩暴露并修复了定点数范围造成的目标距离问题，以及树木类型 `t` 没映射到木棍类型 `s` 的拾取崩溃。

外层导出最终未修改的卡带，在独立 WASM 会话中重放最终提交后的成功输入（排除参数校验失败、没有执行的调用），观察到材料全满、完成面板，以及 X 重开后全部归零。共 34 段、1180 帧，无运行诊断。输入来自模型记录，因此这是独立执行复核，不是独立设计的第二条完整路线。外层另行尝试的一条路线未集齐材料，原始帧保留在缓存中。

这版更清楚，但三种材料主要共用“靠近、按住 X、带回”的操作，只在采集时长、位置和反馈上有差异。还没有验证玩家是否愿意再玩一局。增加材料种类不能代替更有意思的路线选择、风险或取舍。

## 应该蒸馏什么

这个案例适合做一个小型参考包，并在用户说“做个温暖的采集建造游戏”时使用：

- **循环**：找到材料 → 采集 → 带回 → 建造变化 → 再出发。
- **反馈**：采集进度、掉落物、携带状态、交付动作、小窝阶段变化。
- **画面约束**：背景低对比；角色、材料、目标可辨认；128×128 下先检查真实尺寸。
- **声音任务**：采集、拾取、交付、完成各有反馈；音乐与音效分配声道，最终需要人工试听。
- **常见失败**：材料颜色多了但操作完全相同；界面计数可见但材料来源不明；完成了代码却没有验证正常通关。
- **验收证据**：最终卡带从零资源到建成、再重开的一条可复现输入路线和真实帧。

最有价值的内容是具体的设计取舍、失败征兆和验证方法。参考包不应把“加入三种材料”等同于“增加乐趣”。后续应固定提示词、模型与预算，对比不提供参考包和按需提供参考包的结果，并让玩家盲测可读性、操作感和继续玩的意愿。
